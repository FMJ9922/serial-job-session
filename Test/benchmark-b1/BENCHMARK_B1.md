# serial-job-session Benchmark B1 冻结规范

本规范以 `spec.py` 为机器可读来源，验收清单正文与其中的 `CHECKS` 一致。正式启动时冻结规范、公共任务、差异提示、技能文件及各初始工程基线哈希；运行后不得修改要求、编号或分母。

## 实验与调度

六组各运行一次；唯一主分数为通过的验收项数（0–100）。时间、token、费用、压缩、子 agent 及返工仅附加报告，无法准确取得时标记缺失。

- Demo/AITest：gpt-6.1-sol，使用技能。
- Demo1/AITest：gpt-6.1-sol，自主编排。
- Demo2/AITest：gpt-6.1-terra，使用技能。
- Demo3/AITest：gpt-6.1-terra，自主编排。
- Demo4/AITest：gpt-5.6-luna，使用技能。
- Demo5/AITest：gpt-5.6-luna，自主编排。

根目录均为 `E:/Test`。顺序固定为 Demo1 → Demo2 → Demo5 → Demo → Demo3 → Demo4，每次仅运行一组，后组不见前组成果与分数。六组使用同一 CLI 调度、high 推理强度；启动前验证实际模型，禁止替换。整个参赛团队并发最多三个 agent，含主 agent 与全部后代。

初始模板采用相同 Unity 2022.3.62f2 URP 工程与 MCP 包，产品名各异以隔离存档。只交付 Unity 工程，不要求独立构建或 Steam SDK。技能组使用冻结 v5.2.2 及运行工具，全 AI、每卡最多返工三次、失败后继续独立任务，关闭估分计时和飞书同步，不设任务卡或 token 总量上限。对照组禁止读取调用该技能，但可自建计划及交接机制。其余工具、权限、公共任务和验收完全相同。

不强制换会话、不清空上下文、不设置续接轮数。允许自主分工、压缩与恢复，不接受人工业务答疑或救援。各组只操作自己的工程、存档、日志和 Unity 实例，禁止查看其他组实现、会话、历史与成果。记录工具轨迹核查隔离；目录隔离不是操作系统级安全边界。

六组同等可用 Unity 技能、官方文档、包和资源工具。可生成资源、程序化制作资源、使用内置资源及有许可必要字体，禁止导入现成游戏或整套业务框架。外部生成模型只用于美术、音乐、音效，不得用于代码、编排或评审。

## 终止、暂停与封存

以下最先发生即终止：主 agent 最终答复、明确放弃/不能继续、累计有效运行24小时、用户主动终止。最终答复即交卷，不按自报完成率续时。选择等待人工处理视为未完成交卷，不提供业务指导；不另设无进展终止规则。

从正式任务首次发送开始计时，含思考、子 agent、编译、资源生成、自测及自行排错。平台断网、服务不可用、账号接入等有记录的基础设施故障暂停计时，恢复原会话/成果继续。参赛代码引起的编译、包配置、Unity 崩溃和游戏故障继续计时且评委不代修。提前交卷不奖励，耗满不扣分。

终止后停止主 agent、全部后代及仍会写入的工具任务，封存磁盘成果、日志和必要存档；未保存编辑器状态不计交付。审计只在副本进行，无反馈修复机会。读他组成果或用错模型标记实验无效，不冒充低分。用户中止的运行记录快照分数及提前中止标记，不与正常结果等同。

# Benchmark B1：三维积木消除游戏

在分配给你的 Unity 2022.3.62f2 URP 工程中，从现有空白模板实现可玩的三维积木整面消除游戏，完成下方全部公开要求。角色指玩家档案。交付完整 Unity 工程，无需独立构建或 Steam SDK。架构、文件名、JSON 字段、UI 技术、布局、镜头、美术和计分公式自行决定，无统一业务 API。

自主决策，不接受人工答疑、救援或补充需求；遇到选择自己决定。可以创建、复用、结束 subagent，后代也可分工，但整个团队同时最多三个开发 agent（含你本人及全部后代），全部必须使用本组精确模型和 high 推理强度，禁止替换。可以自主压缩上下文和恢复工作，不强制换会话、清空上下文或限制续接轮数。自行保存必要交接信息和命名空间/Unity 实例标识，续接后核对自身工程。

只操作分配给你的工程、存档、日志和 Unity 实例。加载 Unity MCP 工具/专业技能，先核对目标实例和 project path；不得改动其他编辑器。保留产品名的存档隔离设置。不得读取其他组实现、会话、日志、Git 历史或成果，也不得在其他工程搜索答案。审计记录会核查越界与模型使用。

Unity 专业技能、官方文档、包管理、资源工具均可使用。允许自行生成或程序化制作资源，使用 Unity 内置资源和有许可的必要字体；禁止导入现成游戏或整套业务框架。外部生成模型仅能用于美术、音乐和音效，不能代写代码、设计编排或评审。资源必须随工程交付或由工程内代码重复生成。

你有最多24小时有效运行时间，不限制 token 或任务卡总数。你的最终答复即交卷并停止团队，不会因自报低完成率获得续时；明确放弃或等待人类处理也视为未完成交卷。自行排查实现造成的编译、包和游戏故障，这些耗时计入运行时间。平台基础设施故障由调度器记录并暂停计时，不提供业务指导。提前交卷不加分，耗满时间不扣分。交卷前保存所有资产并结束全部写入任务，提供简短操作说明：启动场景、操作、计分公式、存档位置及资源加载方式。

唯一主分数为100项中实际通过的项数，每项1分，仅0/1，无部分分。一项含多个场景时必须全部通过。除明确玩家流程的项目外，允许审计独立运行原始模块验证；自报完成、截图或类的存在不等于通过。所有验收要求公开且运行中不追加；时间、费用、token等只作附加记录。

### 菜单与完整流程

- **001** 按交付说明打开入口场景并进入 Play Mode，直接出现可操作的主菜单。
- **002** 主菜单“进入游戏”能经由角色创建或选择进入可玩的新局。
- **003** 主菜单能够进入设置，再返回主菜单，按钮和导航继续有效。
- **004** “退出游戏”在 Editor 中安全退出 Play Mode，不关闭其他编辑器。
- **005** 局内能够暂停、进入设置、返回原局并继续操作。
- **006** 未结束的一局返回主菜单后，能够继续该局。
- **007** 存在未结束存档时，“继续”与“新游戏”行为区分明确；选择继续不会初始化为新局。
- **008** 完成创建角色、开始游戏、设置、保存、继续、结束及查看排行榜的整合流程，无异常或错误日志。

### 三维棋盘与消除

- **009** 棋盘具有两个水平维度及高度维度，尺寸至少为 4×4×8 个单元。
- **010** 至少提供四种几何形状不同的积木，每种由四个单元立方体组成；仅平移或旋转相同不算新形状。
- **011** 每种积木的四个单元均通过共享面连通。
- **012** 至少一种积木的四个单元中心不共面，体现真正三维形状。
- **013** 有可用出生空间时，生成积木不越界、不与已锁定积木重叠。
- **014** 未暂停时，当前积木会按所声明的节奏自动下降。
- **015** 两个水平轴的边界碰撞均能阻止越界。
- **016** 棋盘底部碰撞能阻止积木穿底。
- **017** 当前积木不能穿过或重叠已锁定单元。
- **018** 旋转遇到边界或占用单元时，结果保持合法；可拒绝旋转或采用合法修正。
- **019** 锁定后，积木的四个单元准确写入棋盘，不丢失、不重复。
- **020** 锁定后正常生成下一块，不同时出现多个当前积木。
- **021** 一个水平面全部填满后，正确消除该面。
- **022** 未填满的水平面不消除；仅填满其中一行也不消除。
- **023** 同时填满多个水平面时全部正确消除，并使上方单元按消除面数正确下降。
- **024** 出生位置被阻塞时进入游戏结束状态，不无限重试生成或覆盖旧单元。

### 操作与三维可读性

- **025** 玩家能够沿第一个水平轴正、反方向移动积木。
- **026** 玩家能够沿第二个水平轴正、反方向移动积木。
- **027** 玩家能够绕两个不平行的轴旋转积木。
- **028** 软降实际加快下降，并保持正确碰撞。
- **029** 硬降落到最近合法位置并锁定，不穿过障碍。
- **030** 玩家可调整镜头，至少从两个不同方位观察棋盘和积木。
- **031** 提供落点预览，显示位置与实际硬降结果一致，覆盖所有积木种类。
- **032** 游戏内操作说明覆盖移动、旋转、下降、镜头和整面消除规则，与实际实现一致。

### HUD、计分与局内状态

- **033** HUD 实时显示当前分数，与实际计分状态一致。
- **034** HUD 实时显示已消除的水平面数量。
- **035** HUD 显示下一块预览，与随后实际生成的积木一致。
- **036** HUD 显示当前玩家档案，与当前存档归属一致。
- **037** 消除会获得正分；单面和多面场景的结果符合交付说明中的确定性计分公式。
- **038** 游戏结束显示最终成绩；重新开始后棋盘、分数和消除计数重置，角色保持正确。
- **039** 暂停期间重力、落锁和计分停止推进。
- **040** 恢复游戏后，棋盘、当前积木与分数延续暂停前状态，无重复生成或结算。

### 玩家档案

- **041** 可以创建并命名玩家档案，支持中文和英文名称。
- **042** 至少三个档案能够同时存在，重启后仍可找到。
- **043** 档案列表可选择当前玩家，选择结果实际生效。
- **044** 档案具有稳定且互不混淆的标识；空名称、重复名称和路径特殊字符得到安全、明确的处理。
- **045** 重命名档案不丢失其存档、成绩或排行榜归属。
- **046** 确认删除一个档案后，仅删除目标档案及其关联数据，不影响其他档案。
- **047** 取消删除不改变任何档案或存档。
- **048** 切换档案后，主菜单、HUD 和继续游戏入口均对应新选择的档案。

### JSON 存档与续局

- **049** 玩家档案及局内进度使用可解析的 JSON 持久化，包含中文时仍能正确读写。
- **050** 保存并恢复完整棋盘中的全部已锁定单元，位置和类型一致。
- **051** 保存并恢复当前积木的形状、位置及朝向。
- **052** 保存并恢复后续积木生成所需状态，恢复后至少连续三块与保存前预期序列一致。
- **053** 保存并恢复分数、消除计数及继续游戏所需的局内阶段状态。
- **054** 未结束的一局返回主菜单时，当前进度实际落盘。
- **055** 玩家在局内可主动触发保存，收到与实际写入结果一致的反馈。
- **056** 关闭并重新打开 Editor 后，能够加载并继续未结束的一局，棋盘与进度一致。
- **057** 三个角色分别保存不同局面，交替加载及重启后均无串档。
- **058** 同一存档重复加载不会产生重复积木、重复加分或重复结算。
- **059** 新角色没有局内存档时，继续入口行为安全且明确，不读取其他角色数据。
- **060** 开始新局时清除该角色旧局内状态，同时保留角色身份及历史成绩。

### 音乐与音效设置

- **061** 游戏实际播放非静音背景音乐，能够在运行中验证音频输出。
- **062** 至少三个不同游戏或 UI 事件会实际触发音效，包含锁定和消除事件。
- **063** 音乐音量可实时调节；零值静音、中间值降低音量，且不改变音效音量。
- **064** 音效音量可实时调节；零值静音、中间值降低音量，且不改变音乐音量。
- **065** 两类音量设置在退出 Play Mode及重新打开 Editor 后仍正确恢复。
- **066** 菜单、设置、局内往返五次，背景音乐不重复叠加，音量设置不意外重置。

### 中英文本地化

- **067** 设置中提供中文和英文选择，运行中切换立即生效。
- **068** 主菜单中的全部固定用户可见文本均有正确的中英文版本。
- **069** 设置及改键界面中的全部固定用户可见文本均有中英文版本。
- **070** HUD、暂停及游戏结束界面中的全部固定用户可见文本均有中英文版本。
- **071** 档案管理和排行榜中的全部固定用户可见文本均有中英文版本；玩家自定义名称不被错误翻译。
- **072** 操作说明与玩法规则均有中英文版本，语义与实际操作一致。
- **073** 语言选择在重新打开 Editor 后保持。
- **074** 在 1920×1080 Game View 下检查上述页面，中文无缺字方框，两种语言均无导致信息不可读的截断或遮挡。

### 键位映射

- **075** 改键界面能够重新绑定两个水平轴的四个移动动作。
- **076** 改键界面能够重新绑定两个旋转轴的动作。
- **077** 改键界面能够重新绑定软降、硬降和暂停动作。
- **078** 改键后，新按键实际驱动目标动作；旧按键不再驱动该动作，除非仍被明确绑定。
- **079** 按键冲突得到明确处理，不静默导致一次按键执行互相冲突的动作。
- **080** 取消按键捕获后，原绑定保持不变。
- **081** 修改后的绑定在重新打开 Editor 后实际生效，界面显示也一致。
- **082** 恢复默认键位后，界面及实际操作均回到所声明的默认配置。

### 本地排行榜

- **083** 游戏提供可访问的本地排行榜页面；没有成绩时显示明确的空状态。
- **084** 正常结束一局后，记录实际最终分数及对应玩家档案。
- **085** 多个不同成绩按分数从高到低正确排列。
- **086** 相同分数采用交付说明中的固定次序，重复打开不随机变化。
- **087** 至少支持显示前十名；准备十二条不同成绩时，前十名取舍正确。
- **088** 排行榜数据在重新打开 Editor 后仍保持。
- **089** 档案重命名后，历史成绩仍归属原档案，不串给同名或其他档案。
- **090** 同一局成绩只入榜一次；暂停、续局和重复打开结算页面不会重复写入，未结束的局不当作最终成绩。

### Addressables

- **091** Addressables 配置及本地资源目录可正确构建，运行时能够加载该目录。
- **092** 至少一种实际用于游戏的预制体通过 Addressables 加载，使用加载结果生成对象。
- **093** 至少另一类实际使用的资源通过 Addressables 加载，如材质、纹理、UI 或音频。
- **094** 异步加载完成前，不访问未就绪对象或放行依赖该资源的操作；完成后正常进入目标流程。
- **095** 交付资源完整，本地目录构建后，重新打开 Editor 可离线完成这些资源的加载。
- **096** 游戏往返五轮后，局内资源句柄得到释放或维持有界的明确缓存，不随每轮操作持续增加。

### 资源完整性

- **097** 所有积木有实际可见的几何与材质，视觉占格与逻辑占格一致，单元分界可辨认。
- **098** 棋盘边界、场景和照明资源完整，在 URP 下可正确显示，无丢失材质或不可见的必要物体。
- **099** 菜单、设置、档案、排行榜及 HUD 所需 UI、字体等资源均随工程提供，不依赖未交付的本机私有文件。
- **100** 至少一份音乐和三种音效资源随工程提供或由工程内代码可重复生成；没有必须依赖私人账号下载的缺失资源。
