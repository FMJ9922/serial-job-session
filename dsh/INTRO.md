# 串行任务会话（serial-job-session for DSH）

> 插件版本 `5.1.1`；skill 协议版本 `5.0.0`（`VERSION`）。两者独立演进，升级插件不会让已有实例报 `TEMPLATE_CHANGED`。
>
> English: [INTRO.en.md](INTRO.en.md)

**一句话**：把 AI 的长任务变成「有合同、有版本、有证据、可回放」的串行作业流——断会话不丢进度，验收不靠印象。

## 它解决什么问题

| 常见困境 | 本工作流的做法 |
|---|---|
| 任务跨会话、跨天就丢了进度 | 进度写进实例文件（追加式日志），不依赖聊天记忆 |
| “做完了”没有证据，评审靠感觉 | 每张任务卡有合同、必验项与证据路径，独立 reviewer 逐项判定 |
| 返工失控、越做越偏 | 首实现后默认最多返工 3 次；失败保留成果，不阻塞独立任务 |
| 人不在场时 agent 自己“授权” | 三种决策模式（人工主导 / 条件自治 / 全 AI），授权边界写进合同，agent 不能冒充人类批准 |
| 多 agent 协作、交接成本高 | 角色会话复用 + 最小交接包；父子任务共用同一实例，不复制框架 |
| 状态散在聊天记录里，无法审计 | JSONL 日志是唯一事实源，`check` 可重放，`state` 可重建 |

## 设计上为什么轻

- **共享方法、实例只存数据**：新建实例只有 4 个文件（`run.json`、`state.json`、两条 JSONL），不复制模板、不生成每张卡的 Markdown。
- **只追加、不改写**：已提交事件不修改，修订是新事件；失败记录保留。
- **快照可丢弃**：`state` 只是投影，`check` 校验、`rebuild` 重建。
- **模块按需加载**：估分计时、飞书镜像默认关闭；关闭时不探活、不访问远端。
- **一个入口**：`init / context / start / apply / handoff / check / rebuild / recover / stats / sync`。

## 优点

- **随时可停可续**：`context` 一屏给出目标、授权、当前卡和有限菜单，暂停一周也能接上。
- **人的决定留痕**：审批带来源；工具调用有幂等 `command_id` 与版本检查。
- **可验证、可审计**：日志重放 + 模板完整性检查；模板变化会明确报 `TEMPLATE_CHANGED`，不静默改写历史。
- **成本可控**：上下文预算默认 12000 字符，日志按 20 张卡 / 512 KiB 分片。
- **和 DSH 原生集成**：skill 目录按需加载；`sjs` 工具自动用当前会话工作目录和 Python，不用记路径；参数面板可改解释器、超时、额外参数。
- **失败不洗白**：失败或未知的必验项不会被评分覆盖，只如实记录。

## 适合与不适合

- **适合**：跨会话、多阶段、需要证据的工程任务（UI 改造、重构、迁移、批量修复）；需要独立验收的交付；多人 + AI 混合协作；需要“今天先停，明天继续”的长线工作。
- **不适合**：一次性小改动、纯查询/问答；要求完全无人值守且绝不能留下失败记录的场景——本工作流选择如实记录，而不是掩盖。

## 在 DSH 里怎么用

1. **安装**（二选一，勿混装）：`dsh plugin add github:FMJ9922/serial-job-session`，或本地目录 `dsh plugin add <仓库路径>`。
2. **创建实例**：让 agent 先 `sjs init --dry-run` 确认目标、授权路径、决策模式、失败处置（模式没有默认值，必须明确选）。
3. **日常推进**：在会话里说 `route_key：意图`（如 `界面优化：推进`），或让 agent 直接调 `sjs context` 读取当前卡。
4. **收口**：实现 → 自检 → 独立 reviewer 验收 → 结案，并把有证据的经验沉淀下来。
5. **调参数**：设置 → 串行任务，改解释器 / 超时 / 额外 CLI 参数；保存后下一次 `sjs` 调用生效。
6. **数据在哪**：实例在项目目录内（建议 gitignore），插件参数在 `$DSH_HOME/serial-job-session.json`。

## 插件在 DSH 里提供什么

| 组成 | 作用 |
|---|---|
| skill `serial-job-session` | 会话目录中按需加载，方法说明与 `references/` 资源都从仓库原位读取 |
| 工具 `sjs` | 在会话工作目录调用 `scripts/sjs.py`，JSON 负载走 stdin，返回 CLI 的 JSON |
| 参数面板 | 设置 → 串行任务（插件页也有一份），解释器 / 超时 / 额外参数 + 环境检测 + 只读信息 |
| 本地 JSON 接口 | `GET /serial-job-session/api/state`、`POST /serial-job-session/api/settings`、`POST /serial-job-session/api/probe`（仅同源、要求 JSON 请求体） |

## 注意事项

- 不要把仓库同时复制进 `~/.dsh/skills` 或项目 `.dsh/skills`：同名时文件系统来源会遮蔽插件注册。
- 首次安装带界面部分（`dsh.client`）后，需要**重启一次 Harness** 才会出现面板。
- 需要 Python 3.11+（只用标准库，无 pip 依赖）。
- 面板接口只接受同源请求；参数文件与实例数据都不含密钥。
